02 Tool 계약 (닫힌 레지스트리) NEW · H-A/G

v2의 27 tool을 형식적 계약으로 승격. 공격자-가시 폐포 대신 방어자-집행 폐포: 모든 tool은 통일 봉투로 반환, exec-binding만이 실행 경로. 예외 누출 0 = "전 tool CRSError-only raise" 규율(참조 tool_wrap가 CRSError만 포획 — 라이브 확인, GATE0).

▎ DefResult[T] · tool_wrap · DefToolSpec (Robo Duck 계승)
type DefResult[T] = DefOk[T] | DefErr            # 모든 tool 통일 반환 (예외 누출 0)
class DefOk[T]:   result: T;   action: AgentAction   # AgentAction{stop,append,rewind}
class DefErr:     error: str;  extra: dict;  action: AgentAction

def tool_wrap(fn, pre_hooks=[], post_hooks=[]) -> Tool:   # Ok→DefOk / Err|CRSError→DefErr
    # ★검증정정(H-A): 참조 tool_wrap의 except는 CRSError만 포획 → bare ValueError/TimeoutError는 누출.
    #   규율: 모든 tool 본체는 CRSError로만 raise(값역·타임아웃도 CRSError 래핑). 아니면 except 확장.
    #  pre_hooks  = [legality(spec, world)]      # precond/consumes 검사(§3)
    #  post_hooks = [world_update(spec, world)]  # produces/effect 반영(§3)
    #  예외는 tool_wrap이 DefErr로 승격 — 파이프라인 크래시 금지 (H-A)

DefToolSpec {                                    # 레지스트리 1행 (27 tool)
  id        : DefToolId          # Literal 화이트리스트 (LLM은 고를 수만, 만들 수 없음)
  cat       : sensor|analysis|response|control
  requires  : [Predicate]        # WorldState 전제 (Legality)
  consumes  : [Artifact]         # 필요 아티팩트 (ip_map, sign_key_loc, baseline …)
  produces  : [Artifact]         # 산출 아티팩트
  effect    : Effect | null      # 상태 전이(대응 tool)
  params    : ParamSpec          # 타입된 파라미터(값역검증)
  risk      : LOW|MED|HIGH       # HIGH(비행행동)=operator-confirm
  reversible: bool
  exec      : ExecBinding{ backend, argv_template, secret_params }  # safe-exec 참조(§6)
  T         : SensorEv|Incident|TrustObj|Decision|EnforcedAction   # payload 타입(v2 객체)
}
닫힘 3중 강제 (H-G)
① Decide/Plan 출력 `DefToolId` pydantic 화이트리스트(밖=거부) ② Legality 게이트(precond 미충족=비legal) ③ exec-binding만 실행(자유형 명령 경로 0). "등록된 대응만 집행".
레지스트리 불변식
모든 tool은 requires/consumes/produces/effect/exec **완전 등록**(유령 tool 금지 → E20 dangling 해소). risk=HIGH(send_signed_mode)=operator. exec=safe-exec 계약만. secret=stdin(argv 금지, R6).

03 WorldState/KB + Legality (방어 추론엔진) NEW · H-E/F

v2의 고정 파이프라인을 상태 기반 추론으로 승격 = "자율 에이전트" 서사의 핵심(25점). 방어 WorldState는 테스트베드 posture · 위협상태 · 활성대응 · 획득 아티팩트를 닫힌 어휘로 유지하고, 대응 tool은 precond/consumes로 게이팅된다.

▎ 방어 WorldState 어휘 (닫힌 enum) + Legality
Predicate (posture·recon으로 확보, 런타임 갱신):
  reach(X)       X∈{gcs14556, web8080, uav5762, mongo27017, pfcp8805, net_core, net_sgi}
  signing∈{on,off,unknown}   nas_cipher∈{eea0_first,ok}   ue_isolation∈{none,enforced}
  role_verified(X)           # §5 런타임 해석·검증 완료 (provenance=verified)
  threat(domain,level)       # Trust/Impact 산출 (command:Red …)
  applied(rule)              # 이미 적용된 대응 (멱등·recover 대상)  in_flight
Artifact (produces→consumes 연결점):
  ip_map        # role→container→IP 해석 결과 (resolve_targets produces)
  sign_key_loc  # gcs_c2 signer-shim 위치 (mdg는 키 미보유)
  baseline(rtt,loss)         pid(container)   # nsenter 대상 PID
Effect: SetResponse(rule) · Contain(container) · Escalate(operator)

Legality(spec, world) ⇔ (spec.requires ⊆ world.facts) ∧ (spec.consumes ⊆ world.artifacts)
# 예: nsenter_input_drop.consumes=[pid(target)] → resolve_targets가 pid 산출 전엔 비legal
#     send_signed_mode.requires=[reach(gcs14556), role_verified(gcs)]  consumes=[sign_key_loc]
#     → 서명경로 미검증·shim 미확인 시 자동 차단 (허위 대응 방지)
방어 조합 창발 (레시피 없이) Decide LLM은 목표(위협 완화) + WorldState + legal 대응의 pre/effect만 받는다. 예: "command 도메인 Red + 5762 ESTAB" → WorldState가 pid(uav_ue) 보유 시 nsenter_input_drop이 legal → 선택. 우리가 "탐지 다음 차단"이라 하드코딩하지 않음. produces/consumes가 recon→resolve→respond 체인을 자동 성립시킴(E23 동시공격 = 다중 legal 대응 집계).

04 에이전트 루프 (LangGraph StateGraph · 결정론 종료) NEW · H-B/D

LangGraph StateGraph (노드=SENSE/CORRELATE/TRUST/IMPACT/ORIENT/POLICY/RECOVERY/DECIDE/ACT/VERIFY · 조건부 엣지=수치 라우팅): 틱(그래프 1회 실행): SENSE : (백그라운드 Collector가 async push) 턴 경계에서 WorldState merge ← 관측 non-blocking(G4) REASON : phase-LLM이 legal tool 중 선택 (Orient 또는 Decide phase) ACT : tool_wrap 실행 = pre_hook[legality] → 본체(safe-exec) → post_hook[world_update] OBSERVE : DefResult(payload) 누적 → 다음 판단 TERMINATE(결정론): world_update 후 goal_reached(위협해소 or 대응완료)면 AgentAction(stop) — LLM-terminate 아님(중첩스키마 실패 회피). 드라이버가 CampaignResult 조립. 드라이버(루프 밖): stop OR max_pivots/k_dry/max_iters → 종료. 안전행동(operator LAND)은 예산면제(G10)
phase 2곳만 LLM (H-D)
Orient phase: correlate_window·compute_trust·compute_impact(결정론) 실행 후 LLM이 근거·신규성 1회 서술. Decide phase: select_policy·rank_recovery(결정론) 후 LLM이 6단계+게이트 1회 판단. 나머지 결정론.
LLM 권한경계 (E12) 형식화
수식/임계값이 수치·게이팅 권위. LLM은 (a)근거 (b)주의 상향만 (c)신규성 플래그. 더 관대한 행동 자동유발 불가. temp=0·structured output·StrictUndefined·빈프롬프트 가드(H-P). 렌더실패/오류→결정론 폴백표(G6).
